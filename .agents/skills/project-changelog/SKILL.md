# CHANGELOG Maintenance
Target: `CHANGELOG.md`

Use the project's existing format when present. Otherwise maintain `## Unreleased`. Never invent versions or release dates. Record meaningful changes, not every edited file. Suitable categories include Added, Changed, Fixed, Security, Deprecated, Removed. Avoid whitespace-only, comments-only, temporary debugging, or internal cleanup with no release relevance.
